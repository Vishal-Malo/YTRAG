# LLMs

## What is an LLM?

An LLM (Large Language Model) is a model used to generate text based on the provided context. It is trained on large amounts of data and generates text by predicting the next likely token based on the tokens that came before it and the context provided to it.

For YTRAG, the LLM will eventually receive a user question along with relevant information retrieved from a YouTube transcript and generate an answer based on that context.

## Tokens

A token is a basic unit of text processed by an LLM. A token can represent a word, part of a word, punctuation, or other pieces of text. Sometimes a single word can be divided into multiple tokens.

Tokens matter in YTRAG because the amount of information provided to and generated by the LLM is measured in tokens. More tokens generally mean more processing and potentially higher cost.

Therefore, we should avoid sending unnecessary information to the LLM and provide only the relevant information required to answer the user's question.

## Context Window

A context window is the maximum amount of tokenized information that a model can consider at once.

The context can contain things such as:

- System instructions
- User question
- Retrieved information
- Conversation history
- Other information provided to the model

For YTRAG, we should not send an entire YouTube transcript to the LLM for every question. Instead, we should retrieve the relevant parts of the transcript and provide those parts as context to the LLM.

For example, if the answer to a question is discussed around 47:32 of a two-hour video, YTRAG should try to retrieve the relevant transcript chunks instead of sending the complete two-hour transcript.

## Temperature

Temperature controls how varied or predictable the LLM's generated output can be.

A lower temperature generally produces more predictable and consistent output, while a higher temperature generally allows more variation in the generated response.

Temperature does not give the model more knowledge. It mainly affects the way the model selects tokens while generating the response.

# Prompting

## System Prompt

A system prompt contains instructions that define how the LLM should behave while generating a response.

It can specify things such as:

- What the LLM should do
- How it should behave
- What information it should use
- Constraints it should follow
- The expected response format

For YTRAG, a system instruction could tell the LLM to answer using the provided YouTube transcript context and avoid making up information that is not present in that context.

## User Prompt

A user prompt is the instruction or question provided by the user.

For example:

> "What did the speaker say about embeddings?"

The user prompt represents what the user wants the LLM-powered application to accomplish.

## Prompt Engineering

Prompt engineering is the process of designing and structuring prompts or instructions so that an LLM produces useful, reliable, and appropriately formatted results.

It can involve:

- Instructions
- Context
- Constraints
- Examples
- Expected output format
- Desired model behavior

Prompt engineering is not limited to creating a system prompt from a user prompt.

# Embeddings

## What are embeddings?

An embedding is a numerical representation of a piece of text that captures useful semantic information about that text.

The text can be a sentence, paragraph, transcript chunk, document, or user query.

An embedding can be represented as a vector of numbers. This vector can be considered as a position in a high-dimensional vector space.

## Why are embeddings needed?

Keyword-based search may fail to identify relevant information when the words used in the user's query are different from the words used in the transcript.

For example:

> User: "How does Python connect to a database?"

> Transcript: "The application establishes a connection with PostgreSQL using a database driver."

The exact words in the user query and transcript are different, but their meaning is related.

Embeddings allow YTRAG to represent both the user query and transcript chunks as vectors that capture semantic information. This allows us to identify transcript chunks that are semantically relevant to the user's question even when the exact keywords are different.

## Semantic Similarity

Two pieces of text are semantically similar when their embeddings are close to each other according to a chosen similarity or distance measure.

For example, the following sentences have similar meanings:

> "Python is used to build APIs."

> "Python is commonly used for developing web services."

Their embeddings would ideally be close to each other in the vector space.

For YTRAG, the embedding of the user's query can be compared with the embeddings of transcript chunks to identify the chunks that are most relevant to the user's question.

# Day 2 Challenge

## If an LLM can already answer questions, why do we need RAG?

An LLM has knowledge learned during its training, but it does not automatically have access to every private, external, or newly provided document.

For example, suppose I have a personal document containing information that was not part of the model's training data. The LLM cannot automatically access that document just because it exists.

RAG helps by retrieving relevant information from an external source and providing that information to the LLM as context.

The LLM then uses that provided context to generate the answer.

The important distinction is:

**RAG retrieves relevant information. The LLM generates the answer.**

# Day 2 Mini-Test

## Q1. Can we put a 100,000-token YouTube transcript into the LLM for every question?

Not necessarily. The transcript may exceed the model's context window. Even if it fits, sending the entire transcript for every question can consume unnecessary tokens, increase cost, and include a lot of irrelevant information.

YTRAG should retrieve the relevant transcript chunks instead.

## Q2. What is the difference between a token and a context window?

A token is a basic unit of text processed by the LLM.

A context window is the maximum amount of tokenized information the model can consider at once.

For example, a context window could contain:

- System instructions
- User question
- Retrieved transcript chunks
- Conversation history

## Q3. What is the difference between an LLM and RAG when answering a question about a video?

RAG is responsible for retrieving the relevant information from the video transcript.

The retrieved information is then placed into the context provided to the LLM.

The LLM uses that context to generate the final answer.

The LLM does not search through its entire training data every time a question is asked.

## Q4. Does increasing temperature give the model more knowledge?

No.

Increasing temperature does not give the model additional knowledge or information.

It changes the variability of token selection during generation, which can result in more varied responses.
